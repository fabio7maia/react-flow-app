## The pieces

- **Screen**: a component plus the actions it can dispatch, with payload types. It never imports another screen. See [screens](/guides/screens/).
- **Action**: a named event with an optional payload. The screen says *what happened*, not where to go.
- **Flow**: steps (each one a screen) and **transitions**: for each action of each step, a target. A target is a step, another flow
  (`goto`), a `branch` that decides between declared targets, or an `effect`. See [flows](/guides/flows/).
- **Engine**: runs the transitions and keeps the history. It has no DOM, so it runs in Node tests and can be driven without rendering.
- **Events**: every navigation emits an ordered set of events with one `navigationId`. See [events](/guides/events/).
- **Adapters**: listen to the events or the engine: the browser URL and back button, scroll restoration, analytics.
  See [URLs](/guides/urls/) and [analytics](/guides/analytics/).
- **Provider**: `FlowProvider` owns one engine and renders its current step. See [React](/guides/react/).

Because transitions are data, the same graph feeds the diagram, validation and [generated tests](/guides/testing/).
