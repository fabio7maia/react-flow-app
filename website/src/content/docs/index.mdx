	Install it with `npm install react-flow-app@alpha`. v2 stays on `latest` and keeps receiving fixes. See [releases](/reference/releases/)
	for what alpha, beta and rc mean here.

```ts
checkoutFlow.transitions({
	cart: { checkout: branch(['payment', goto('auth', 'login')], (_, p) => (p.loggedIn ? 'payment' : goto('auth', 'login'))) },
	payment: { pay: branch(['success', 'failure'], (_, p) => (p.ok ? 'success' : 'failure')), cancel: 'cart' },
	failure: { retry: 'payment' },
	success: { finish: goto('home', 'dashboard') },
});
```

Because navigation is data, the library can draw every flow, generate tests from the graph, send analytics from one event stream, and
type everything end to end.

<CardGrid>
	<Card title="Event based" icon="rocket">
		Screens dispatch actions such as `pay` or `cancel`. They never import other screens or call `navigate`.
	</Card>
	<Card title="A diagram of every flow" icon="seti:graphql">
		`toMermaid(toGraph(app))` draws the flows from the code. `react-flow-app check` keeps the diagram in the repo and shows the changes
		in every PR.
	</Card>
	<Card title="Generated tests" icon="approve-check">
		`getPaths` produces one test per reachable step, and `coverage()` lists the transitions no test walked.
	</Card>
	<Card title="Analytics from one event stream" icon="information">
		An ordered event contract, with GA4 and Segment adapters: page views, funnels, opt-in actions and consent.
	</Card>
	<Card title="Typed end to end" icon="seti:typescript">
		Actions, payloads, cross-flow targets, URL params, screen metadata and events, with intellisense, through one `Register`.
	</Card>
	<Card title="Headless core" icon="setting">
		The engine has no DOM. URL, browser back button and scroll restoration are optional adapters, and it runs in Node tests.
	</Card>
</CardGrid>
